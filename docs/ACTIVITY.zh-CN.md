# 代码小花园的数据口径

**简体中文** · [English](ACTIVITY.en.md)

## 贡献日历

GitHub 使用公开贡献日历 HTML，Gitee 使用公开主页日历。解析日期、每日次数和平台总数，并要求每日合计与官方总数一致、日期连续且范围合理。读取的是公开访问可见的结果，不保证包含登录后才可见的私有活动。

“总”是两平台已返回贡献相加，不做跨平台 Commit 去重。平台返回的最近一年范围可能不同；未知日期与真实零值分开显示，部分缺失以虚线标记。公开页面不是稳定的个人日历 API，结构变化时需要维护解析器。

## Push 足迹

GitHub 和 Gitee 的公开用户事件接口分别采集。只接受配置账号、配置公开仓库中的 PushEvent，保留分支推送，排除删除、标签和无变化事件。主键为平台加事件 ID，重复采集不会增加次数。

Push 按北京时间归日，不等于贡献数，也不等于 Commit 数。接口有近期历史、分页和数量限制，首次补录只能覆盖实际返回的记录。每天一次的采集可能在高活动量或长时间停机时漏过接口窗口，不宣称永久完整。已有事件不跨平台去重。

## 同步与故障

- systemd 每天 04:00 Asia/Shanghai 执行，日历与事件统一核对。
- 页面只访问同站 `/api/activity` 缓存；切换平台不会请求上游。
- HTTP 条件缓存、非阻塞进程锁、SQLite 事务和事件主键减少重复工作。
- JSON 通过临时文件和原子替换发布，源数据失败时保留上次成功结果。
- 没有成功记录时显示待同步；格式变化不会变成一整年全零。
- UI 按每日计划检查过期，允许一小时延迟；当前打开的页面不会自动推送更新，重新打开会读取新缓存。

## 文件

`blog/runtime/private/activity.sqlite3` 保存每日观测和事件历史；HTTP 原响应只放 private 缓存。公开 JSON 只含规范化计数、来源、范围、时间与最近事件，不公开 Commit 消息或邮箱。private 目录不是网站根目录的一部分。

在 `blog/activity/config.json` 修改仓库范围不会自动删除历史。新的项目展示文件夹也不会自动扩大事件采集范围。先备份数据库，再做改变历史口径的数据迁移。

检查命令见[部署说明](DEPLOYMENT.zh-CN.md)。单元测试使用临时数据库与构造输入，不依赖在线账号数据。
